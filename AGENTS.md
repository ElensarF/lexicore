# Repository Instructions

## Project Rules

Before making changes in this repository:

1. Read the README, package/build config, test config, and relevant source files.
2. Follow the existing architecture and naming conventions.
3. Do not introduce new dependencies without approval.
4. Do not modify public APIs, schemas, migrations, or deployment config unless explicitly required.
5. Prefer small, reviewable commits/diffs.

## Verification Commands

Use the repository’s actual commands. If available, run the relevant subset of:

- install/check dependencies
- lint
- typecheck
- unit tests
- integration tests
- build

Report the exact commands run and their results.

## Code Quality Bar

All changes must be:

- correct,
- tested or explicitly marked as unverified,
- idiomatic for the language/framework,
- minimal,
- secure,
- maintainable,
- consistent with the existing codebase.
